# @repo/pagination

A shared cursor-based pagination implementation used on both sides of the stack, so the API and the React UI agree on the same pagination contract instead of each reinventing it. The core `Pagination` class wraps a query callback keyed by `id` (typically a Prisma `findMany`); calling `.fetch({ limit, cursor })` asks the callback for `limit + 1` rows ordered by `id` ascending starting after `cursor`, then pops the lookahead row off to compute `nextCursor`/`hasNext` without ever running a separate `COUNT` query. Zod schemas under `/validation` (`PaginationRequestMetaSchema`, `PaginationResultSchema`, `PaginationResultMetaSchema`) validate the `cursor`/`limit`/`orderBy` query params on the way in and the `data`/`meta` envelope on the way out, including string-to-int coercion for query-string limits.

On the frontend, the `/hooks` subpath exports `useCursorPagination`, a TanStack Table–compatible hook that keeps a history of cursors per page index so "next"/"previous" navigation works against a `nextCursor`/`hasNext` API response while faking the `rowCount` TanStack Table expects. `/enums` (`SortKeys`, `OrderByDirection`) and a `/__tests__/helpers` subpath for building fixtures round out the package.

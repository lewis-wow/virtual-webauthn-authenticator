# @repo/exception

The shared error model that every service in the monorepo throws and catches, so a failure raised in one layer carries a consistent, serializable shape all the way out to an HTTP response. The base `Exception<TData>` class extends `Error` and adds a static `code`, `message`, and optional `status` (an `@repo/http` `HttpStatusCode`) that subclasses declare, plus an instance `data` payload for structured error details. It can be serialized with `.toJSON()` and turned directly into a `Response` via `.toResponse()`, and reconstructed on the receiving end from a JSON body with the static `Exception.fromResponse()`, which is how a caught exception's `code`/`message`/`status` survive a network hop intact.

The root export also includes `RequestValidationFailed` and `isExceptionShape` (a type-guard factory for narrowing an unknown error shape to a specific exception subclass by its `code`). The `@repo/exception/http` subpath provides ready-made subclasses for common HTTP failure cases — `Unauthorized`, `Forbidden`, `InternalServerError`, `MethodNotAllowed`, `PreconditionFailed`, `FailedDependency`, `UpgradeRequired`, and more — each just pinning a `status`, `code`, and default `message`. Separate `/validation` and `/mappers` subpaths hold the Zod schema used to validate an exception's wire shape and helpers for mapping other error types into this model; apps/nestjs's global exception filter is the primary consumer, converting any thrown error into an `Exception` and calling `.toResponse()` on it.

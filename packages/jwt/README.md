# @repo/jwt

The project's own JWT issuing and verification layer, distinct from better-auth's session/cookie mechanism. The auth-server wires this package's `Jwt`/`Jwks` classes into better-auth's `jwt` plugin `sign` callback, so the tokens that actually get issued are shaped and signed here rather than by better-auth's built-in JWT handling; resource-server apps like nestjs then use this package's `JwtAudience` to verify those tokens against the auth-server's remote JWKS endpoint for a given audience.

`Jwt` wraps `jose` to sign, decode, and verify tokens against a defined `JwtPayload` (registered claims plus custom fields such as `permissions`, `userId`, and `apiKeyId`), `Jwks` generates and retrieves the EdDSA key pairs used for signing through a pluggable `IJwksRepository` (encrypting the private key at rest via `@repo/crypto` — the concrete Prisma-backed repository lives in `@repo/jwks`), `JwtIssuer` is a thin convenience wrapper binding a fixed issuer/audience, and `JwtAudience` verifies a token for one audience against a remote or local JWKS. A set of typed exceptions maps `jose`'s errors (expired, invalid signature, no matching key, etc.) into this codebase's exception model.
